# 멍밥쟁탈전 V1.5 STEP 4
## 새 친구 합류 UI/UX 보정 및 화면 깨짐 수정

현재 구현된 `새 친구 합류` 시스템의 기본 방향은 유지합니다.

현재 구조:

```text
캐릭터 선택 화면
↓
다음 친구 합류 진행도
↓
포인트 충족
↓
친구 만나기
↓
미합류 캐릭터 선택
↓
새 친구 합류
```

이 구조 자체는 적절하므로 대규모 리디자인은 하지 않습니다.

이번 작업에서는 다음 부분을 중심으로 UI/UX를 다듬어 주세요.

---

# 1. 캐릭터 선택 화면의 진행도 정보 개선

현재 하단에:

```text
다음 친구 합류
1 / 8 · 500 P
```

형태로 표시되고 있는데, `1 / 8`과 `500P`의 의미가 한 번에 읽히지 않습니다.

정보를 분리해 주세요.

권장:

```text
다음 친구 합류

함께하는 친구 1 / 8

320 / 500 P
[진행바]

[친구 만나기]
```

또는 현재 공간에 맞게 한 줄/두 줄 구조로 compact하게 구성해도 됩니다.

중요한 것은 다음 두 개념을 명확하게 분리하는 것입니다.

```text
현재 함께하는 친구 수
다음 친구 합류까지 필요한 포인트
```

---

# 2. 진행바에 실제 포인트 반영

진행바는 단순 장식이 아니라 실제 현재 포인트 상태를 반영해야 합니다.

예:

```text
현재 0P
→ 0 / 500 P

현재 250P
→ 250 / 500 P

현재 500P
→ 500 / 500 P

현재 700P
→ 500 / 500 P
```

진행바 표시 자체는 최대 필요 포인트까지만 채웁니다.

보유 포인트가 500P보다 많더라도:

```text
700 / 500
```

처럼 progress를 넘겨 표현하지 않습니다.

필요하다면 별도로 보유 포인트는 기존 포인트 UI에서 확인할 수 있도록 합니다.

---

# 3. 친구 만나기 버튼 상태

현재 포인트가 다음 합류 조건보다 부족하면 `친구 만나기` 버튼은 비활성화 상태로 보여 주세요.

예:

```text
320 / 500 P

[친구 만나기] disabled
```

포인트가 충분해지면 활성화합니다.

예:

```text
500 / 500 P

🎉 새 친구를 만날 준비가 됐어요!

[친구 만나기]
```

단, disabled 상태에서도 스크린리더 사용자가 이유를 알 수 있도록 합니다.

예:

```text
다음 친구를 만나려면 180포인트가 더 필요합니다.
```

---

# 4. 진행 완료 상태 문구

포인트가 충족되었을 때 단순히 진행바만 꽉 차게 하지 말고 짧은 상태 변화를 제공합니다.

예:

```text
새 친구를 만날 준비가 됐어요!
```

또는:

```text
새 친구를 만날 수 있어요!
```

현재 게임 스타일에 더 잘 맞는 표현을 사용합니다.

---

# 5. 미합류 캐릭터 표시

아직 합류하지 않은 캐릭터는 현재처럼 약간 흐린 상태를 유지해도 좋습니다.

다만 너무 투명하게 처리해서 캐릭터 자체를 알아보기 어렵게 만들지는 마세요.

목표:

```text
사용할 수 없다는 것은 알 수 있음
+
어떤 강아지인지 충분히 구분 가능
```

이어야 합니다.

잠금 상태를 색상/opacity만으로 전달하지 않고 접근성 상태도 제공합니다.

예:

```text
퍼그, 아직 함께하지 않은 친구
```

---

# 6. 캐릭터 카드에 개별 포인트 표시 금지

다음처럼 만들지 않습니다.

```text
퍼그 500P
몰티즈 500P
포메라니안 500P
```

새 친구 합류 비용은 견종별 가격이 아닙니다.

비용은 항상:

```text
다음 친구 합류까지 필요한 포인트
```

로 표현합니다.

---

# 7. 캐릭터 선택 CTA 문구

현재 하단 버튼이:

```text
캐릭터 선택
```

이라면 기존에 확정한 2단계 UX에 맞게:

```text
이 캐릭터 선택
```

으로 변경해 주세요.

전체 흐름:

```text
STEP 1
내 댕댕이 선택
↓
[이 캐릭터 선택]

STEP 2
이번 게임 설정
↓
이름
AI 난이도
↓
[게임 시작]
```

을 유지합니다.

# 8. 친구 만나기 modal 구조 개선

현재 `친구 만나기`를 눌렀을 때 표시되는 modal의 기본 목적은 맞습니다.

현재 예:

```text
NEW FRIEND

어떤 친구를 만나볼까?
이번 합류에는 500P가 필요해요.

[미합류 캐릭터들]

```

이 구조를 조금 더 정리해 주세요.

# 9. modal 캐릭터 배치

미합류 캐릭터는 modal 내부에서 균등한 grid 형태로 보여 주세요.

현재처럼 왼쪽에 캐릭터가 몰리고 오른쪽에 큰 빈 영역이 생기지 않도록 합니다.

예:

```text
푸들       퍼그       골든리트리버
웰시코기   몰티즈     포메라니안
비숑
```

또는 화면 폭에 따라:

```text
4 + 3
```

등 자연스러운 grid를 사용합니다.

미합류 캐릭터 수가 줄어들어도 중앙 정렬과 균형이 유지되어야 합니다.

---

# 10. `다음에 만나기` 버튼 수정

현재 화면에서 `다음에 만나기` 버튼이 지나치게 큰 세로형/타원형으로 렌더링되어 화면이 깨진 것처럼 보입니다.

이 부분은 반드시 수정합니다.

현재 문제:

```text
버튼 높이가 비정상적으로 큼
세로형 타원 형태
modal 오른쪽 영역을 과도하게 차지
캐릭터 grid와 시각적 균형이 무너짐
```

`다음에 만나기`는 큰 CTA일 필요가 없습니다.

권장:

```text
[다음에 만나기]
```

를 modal 하단에 일반 secondary button 크기로 배치하거나,

간단하게:

```text
닫기
```

역할로 처리합니다.

버튼 width/height는 기존 멍밥쟁탈전의 일반 secondary 버튼 크기를 사용합니다.

---

# 11. 친구 선택 후 확인

사용자가 미합류 캐릭터를 누르면 바로 포인트를 차감하지 않습니다.

선택 상태를 먼저 보여 줍니다.

예:

```text
퍼그와 함께할까요?

이번 새 친구 합류에는
500P를 사용해요.

현재 포인트 650P
합류 후 150P

[함께하기]
[다시 고르기]
```

`구매`, `가격`, `분양` 등의 표현은 사용하지 않습니다.

# 12. modal 화면 깨짐 전체 점검

현재 modal에서 일부 요소의 width/height 계산이 잘못되면서 화면이 깨져 보이는 문제가 있습니다.

다음 항목을 반드시 점검해 주세요.

- 버튼 height가 비정상적으로 늘어나는 문제
- flex item이 남은 공간을 강제로 모두 차지하는 문제
- `flex: 1` 또는 `height: 100%` 때문에 버튼이 세로로 늘어나는 문제
- grid와 버튼 영역이 같은 flex row 안에서 잘못 stretch되는 문제
- `align-stretch` 때문에 interactive element가 부모 높이를 전부 차지하는 문제
- width/height가 viewport 기준으로 잘못 설정된 문제
- content 길이에 따라 modal height가 과도하게 증가하는 문제

필요하다면:

```css
align-items: center;
flex: none;
height: auto;
min-height: ...;
max-width: ...;
```

등 현재 구조에 맞는 방식으로 수정합니다.

무조건 위 CSS를 그대로 적용하는 것이 아니라 실제 원인을 확인한 뒤 해결합니다.

---

# 13. modal max size

modal은 작은 iPhone에서도 화면 안에 안정적으로 들어와야 합니다.

다음 기준을 확인합니다.

```text
320px
375px
390px
430px
```

modal이 화면보다 커지면 내부 content 영역에만 적절한 scroll을 허용합니다.

전체 page가 이상하게 확대되거나 modal이 화면 밖으로 잘려서는 안 됩니다.

---

# 14. modal 내부 overflow

캐릭터 수는 최초 7종이며 이후 합류할수록 감소합니다.

따라서 7개부터 1개까지 모두 정상적으로 보여야 합니다.

예:

```text
7개
6개
5개
...
1개
```

어떤 수에서도:

- grid가 한쪽으로 무너지지 않음
- 빈 공간이 과도하게 생기지 않음
- 카드가 stretch되지 않음
- 버튼 크기가 변하지 않음

을 확인합니다.

# 15. 하단 진행도 영역 화면 깨짐

메인 캐릭터 선택 화면의 하단:

```text
다음 친구 합류
진행바
친구 만나기
```

영역도 작은 화면에서 깨지지 않도록 점검합니다.

특히:

- 진행바와 버튼 겹침
- 텍스트 줄바꿈 때문에 높이가 비정상 증가
- 버튼이 container 밖으로 나감
- progress bar가 지나치게 좁아짐
- `친구 만나기` 버튼 텍스트 잘림
- 하단 `이 캐릭터 선택` 버튼과 겹침

이 없어야 합니다.

---

# 16. 하단 영역 우선순위

하단은 다음처럼 두 개의 영역으로 명확히 구분합니다.

```text
[새 친구 합류 진행 영역]

[이 캐릭터 선택]
```

두 영역이 하나의 버튼 그룹처럼 보이지 않도록 적절한 간격을 둡니다.

---

# 17. 선택 불가능한 캐릭터 동작

아직 합류하지 않은 캐릭터를 눌렀다고 해서 선택 체크가 이동하면 안 됩니다.

즉:

```text
진도믹스 선택됨

↓

미합류 퍼그 터치

↓

진도믹스 선택 상태 유지
```

퍼그 터치 시에는 합류 상태 안내만 제공합니다.

---

정상적으로 합류하면:

```text

```

완료 UI를 보여 준 뒤 해당 캐릭터를 선택 상태로 전환할 수 있습니다.

권장:

```text

↓
퍼그 자동 선택
↓

```

또는 이름 설정으로 자연스럽게 연결합니다.

# 최종 목표

현재 구현된 새 친구 합류 시스템의 구조는 유지합니다.

다만 사용자에게는:

```text
캐릭터별 가격표
```

가 아니라:

```text
게임을 하면서 포인트를 모음
↓
다음 친구까지 진행도가 올라감
↓
조건 충족
↓
친구 만나기
↓
원하는 친구 선택
↓
새 친구 합류
```
