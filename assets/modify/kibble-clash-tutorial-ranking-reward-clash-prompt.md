# 멍밥쟁탈전 V1.5 — 튜토리얼 순위 보상 / CLASH 규칙 설명 개선 프롬프트

## 작업 목적

현재 튜토리얼은 사용자가 게임 규칙을 다음과 같이 오해할 가능성이 있다.

> "CLASH를 피해서 1등을 하면 된다."

하지만 실제 게임의 핵심 규칙은 단순히 1등만 점수를 받는 구조가 아니다.

각 밥그릇에는 여러 개의 순위별 보상이 존재하며,
CLASH가 발생하지 않고 살아남은 주사위들은 숫자가 높은 순서대로
1등, 2등, 3등, 4등이 되어 각 순위에 해당하는 보상을 획득한다.

따라서 튜토리얼에서 다음 개념을 반드시 명확하게 설명하도록 개선한다.

1. 밥그릇에는 여러 개의 순위별 보상이 있다.
2. 살아남은 주사위는 숫자가 높은 순서대로 보상을 받는다.
3. 반드시 1등을 하지 않아도 점수를 획득할 수 있다.
4. 같은 숫자가 만나면 CLASH가 발생한다.
5. CLASH로 제거된 주사위는 순위 계산에서 제외된다.
6. CLASH 이후 살아남은 주사위를 기준으로 순위가 다시 결정된다.
7. 따라서 높은 숫자뿐 아니라 "살아남는 것" 자체가 중요하다.

---

# 현재 튜토리얼의 문제점

현재 화면에서는 밥그릇 위에 예를 들어 다음과 같은 보상이 표시된다.

```text
50 / 20 / 10 / 10점
```

하지만 신규 사용자는 이 숫자들이 정확히 무엇을 의미하는지 알기 어렵다.

특히 현재 튜토리얼의 메시지가

```text
CLASH를 피해서 1등을 노려보세요
```

와 유사한 방향이라면 다음과 같은 오해가 발생할 수 있다.

- 1등만 점수를 받는다고 생각함
- 2등, 3등도 보상을 받는다는 사실을 모름
- 밥그릇 위의 여러 점수가 왜 표시되는지 이해하지 못함
- 낮은 숫자를 선택하는 전략적 의미를 이해하지 못함
- CLASH가 단순한 패널티라고만 생각하고 순위 재편의 의미를 이해하지 못함

이번 작업에서는 이 부분을 개선한다.

---

# 핵심 튜토리얼 메시지

튜토리얼 전체 메시지는

```text
CLASH를 피해서 1등을 해라
```

가 아니라,

```text
살아남은 주사위가 높은 숫자 순서대로
밥그릇의 순위 보상을 가져간다.
```

로 전달되어야 한다.

그 이후에

```text
같은 숫자는 CLASH로 사라지기 때문에
높은 숫자만 고르는 것이 항상 정답은 아니다.
```

라는 전략적 의미까지 자연스럽게 연결한다.

# 권장 튜토리얼 흐름

## STEP 1. 밥그릇 보상 소개

먼저 특정 밥그릇 하나를 강조한다.

현재 튜토리얼 화면의 1번 밥그릇처럼
여러 순위 보상이 표시된 영역을 하이라이트한다.

예:

```text
50 / 20 / 10 / 10점
```

안내 문구:

```text
밥그릇마다 받을 수 있는
사료 점수가 정해져 있어요!
```

그 다음 각 보상이 순위 보상이라는 것을 알려준다.

가능하다면 튜토리얼 중에만 각 보상 위 또는 아래에 다음 라벨을 임시 표시한다.

```text
1등   2등   3등   4등
50    20    10    10
```

실제 게임 UI에 항상 노출할 필요는 없다.

튜토리얼 설명 중에만 가이드 형태로 표시해도 된다.

---

## STEP 2. 살아남은 주사위의 순위 설명

다음으로 CLASH가 없는 상태에서 여러 주사위가 배치된 예시를 보여준다.

예:

```text
6 / 4 / 2
```

이 경우:

```text
6 → 1등 → 50점
4 → 2등 → 20점
2 → 3등 → 10점
```

처럼 연결 관계를 보여준다.

안내 문구:

```text
살아남은 주사위는
높은 숫자 순서대로 보상을 받아요!
```

이 단계에서 반드시 다음 내용을 알려준다.

```text
꼭 1등이 아니어도 괜찮아요.
살아남으면 순위에 따라 사료를 받을 수 있어요!
```

### 중요

이 문구는 신규 사용자가

> "1등만 의미가 있다"

고 오해하지 않도록 하기 위한 핵심 설명이다.

---

# 시각적 표현 권장안

단순 텍스트 설명만 보여주기보다
실제 게임 요소와 연결해서 보여주는 방향을 우선한다.

예:

```text
[주사위 6] ─────→ [1등 50점]
[주사위 4] ─────→ [2등 20점]
[주사위 2] ─────→ [3등 10점]
```

또는 현재 UI를 유지하면서

- 주사위 6 강조
- 50점 보상 강조
- 연결선 / 화살표 표시
- 다음 주사위와 보상을 순차 강조

하는 방식도 가능하다.

---

# STEP 3. CLASH 설명

순위 보상 구조를 이해시킨 뒤 CLASH를 설명한다.

동일한 숫자가 같은 밥그릇에 배치된 상황을 강조한다.

예:

```text
6 / 6 / 4 / 2
```

안내:

```text
같은 숫자가 만나면 CLASH!
```

보조 문구:

```text
CLASH한 주사위는
보상 경쟁에서 제외돼요.
```

CLASH가 발생한 두 개의 6 주사위가 제거되는 모습을 보여준다.

---

# STEP 4. CLASH 이후 순위 재계산 설명

이 단계가 특히 중요하다.

CLASH 전:

```text
6 / 6 / 4 / 2
```

CLASH:

```text
6 ↔ 6
CLASH!
```

CLASH 후:

```text
4 / 2
```

그리고 실제 보상:

```text
4 → 1등 → 50점
2 → 2등 → 20점
```

처럼 보여준다.

안내 문구:

```text
CLASH한 주사위가 사라지면
남은 주사위끼리 다시 순위를 정해요!
```

또는 조금 더 자연스럽게:

```text
살아남은 주사위 중
가장 높은 숫자가 1등이 돼요!
```

---

# STEP 5. 게임의 전략성 설명

마지막으로 사용자가 다음 내용을 이해하도록 한다.

```text
높은 숫자가 항상 정답은 아니에요.
CLASH를 피하면서 좋은 순위를 노려보세요!
```

또는:

```text
상대와 같은 숫자를 피하면서
더 좋은 보상을 노려보세요!
```

### 기존 문구 수정

기존에 다음과 유사한 문구가 있다면:

```text
CLASH를 피해서 1등을 노려보세요!
```

다음 방향으로 변경한다.

권장안:

```text
CLASH를 피하고 살아남으면
순위에 따라 사료를 받을 수 있어요!
```

또는:

```text
같은 숫자를 피하면서
더 좋은 순위의 보상을 노려보세요!
```

1등만을 목표로 하는 게임처럼 보이지 않도록 한다.

# 추천 튜토리얼 최종 흐름

전체 순서는 아래와 같이 구성한다.

```text
1. 밥그릇에는 여러 개의 보상이 있다는 것을 보여준다.
        ↓
2. 각 보상이 1등 / 2등 / 3등 / 4등 보상임을 알려준다.
        ↓
3. 살아남은 주사위가 높은 숫자 순으로 보상을 받는 것을 보여준다.
        ↓
4. 1등이 아니어도 점수를 받을 수 있음을 알려준다.
        ↓
5. 같은 숫자가 만나면 CLASH가 발생함을 보여준다.
        ↓
6. CLASH한 주사위가 제거되는 모습을 보여준다.
        ↓
7. 남은 주사위 기준으로 순위가 다시 계산되는 것을 보여준다.
        ↓
8. 높은 숫자 + CLASH 회피를 함께 고려해야 한다는 전략을 설명한다.
```

# UX 구현 원칙

튜토리얼 설명을 긴 텍스트 팝업으로만 처리하지 않는다.

가능하면 실제 게임판을 그대로 활용하여

- 해당 밥그릇 강조
- 보상칩 강조
- 주사위 강조
- CLASH 이펙트
- 순위별 보상 연결

등을 통해 직접 보여준다.

사용자는 설명을 읽는 것보다
실제 게임판에서 어떻게 점수가 결정되는지 보는 방식으로 이해해야 한다.

# 기존 튜토리얼 구조와의 통합

현재 이미 구현되어 있는 튜토리얼 흐름을 먼저 분석한다.

새 튜토리얼 시스템을 처음부터 다시 만들지 말고
기존 튜토리얼의 단계 / 오버레이 / 하이라이트 / 다음 버튼 구조를 최대한 재사용한다.

이번 작업에서는 다음 내용을 추가 / 보완한다.

1. 순위별 보상 설명
2. 2등 이하도 점수를 받는다는 설명
3. CLASH 이후 순위 재계산 설명
4. 기존 1등 중심 문구 수정

# 실제 게임 규칙과 데이터 연동

튜토리얼에 표시하는 숫자를 임의로 하드코딩하지 않는다.

실제 밥그릇 보상 데이터와 게임 규칙을 확인해서
튜토리얼 예시가 실제 게임 로직과 일치하도록 한다.

예를 들어 실제 보상 데이터가:

```ts
[50, 20, 10, 10]
```

이라면 이를 그대로 사용한다.

향후 밸런스 조정으로 보상이 변경되어도
튜토리얼이 잘못된 숫자를 보여주지 않도록
가능하면 실제 데이터 소스를 재사용한다.

# CLASH 규칙 확인

구현 전에 현재 게임의 실제 CLASH 처리 로직을 반드시 확인한다.

다음 사항을 코드 기준으로 검증한다.

- 같은 숫자의 주사위가 모두 제거되는지
- CLASH 제거 후 남은 주사위가 재정렬되는지
- 동률이 추가로 존재할 경우 어떤 식으로 처리되는지
- 보상 수보다 살아남은 주사위가 많을 경우 어떻게 처리되는지
- 보상 슬롯이 남을 경우 어떻게 처리되는지

튜토리얼 설명은 반드시 실제 구현 규칙과 일치해야 한다.

게임 로직 자체를 변경하지 말고,
현재 로직을 정확하게 설명하는 것이 이번 작업의 목표다.

# 접근성

튜토리얼에서 보상 관계가 화살표나 색상만으로 전달되지 않도록 한다.

스크린리더 사용 시에도 다음 정보가 이해될 수 있어야 한다.

예:

```text
주사위 6, 1등, 50점 획득
주사위 4, 2등, 20점 획득
주사위 2, 3등, 10점 획득
```

CLASH 예시:

```text
주사위 6 두 개가 충돌하여 제거되었습니다.
남은 주사위 4가 1등, 50점을 획득합니다.
```

화면에 표시되는 여러 개의 장식 요소가
스크린리더에서 중복으로 반복 낭독되지 않도록 한다.

# 모바일 화면 대응

현재 게임 화면은 이미 많은 정보가 표시되고 있으므로
튜토리얼 요소 때문에 화면이 깨지거나 기존 UI가 밀리지 않도록 한다.

특히:

- Toss Miniapp 상단 영역
- 작은 모바일 화면
- Safe Area
- 하단 버튼 영역
- 캐릭터 / 점수 영역
- 밥그릇 보상 영역

을 확인한다.

튜토리얼 설명은 기존 레이아웃에 공간을 추가하는 방식보다
overlay / tooltip / spotlight 형태를 우선한다.

# 구현 범위 제한

이번 작업의 핵심은

**게임 규칙을 변경하는 것이 아니라
현재 게임의 순위 보상 구조를 신규 사용자에게 정확하게 설명하는 것**이다.

따라서 다음 항목은 임의로 변경하지 않는다.

- 밥그릇별 실제 보상값
- CLASH 판정 로직
- 주사위 선택 로직
- AI 로직
