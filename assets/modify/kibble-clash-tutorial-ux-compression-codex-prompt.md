# 멍밥쟁탈전 V1.5 — 튜토리얼 UX 압축 및 가독성 개선 프롬프트

## 작업 목적

최근 튜토리얼에 아래 내용을 추가했다.

- 밥그릇별 순위 보상 설명
- 1등이 아니어도 점수를 받을 수 있다는 설명
- CLASH 이후 남은 주사위 기준으로 순위가 다시 정해진다는 설명

규칙 설명의 정확도는 좋아졌지만,
현재 구현은 튜토리얼이 9단계까지 늘어나면서
캐주얼 게임에 비해 설명량이 과도해졌고,
말풍선 내부 텍스트가 지나치게 좁게 배치되어 가독성이 떨어진다.

이번 작업의 목표는
**새 규칙 설명을 삭제하지 않고, 더 짧고 직관적으로 압축하는 것**이다.

---

# 현재 확인된 문제점

## 1. 튜토리얼 단계가 너무 많음

현재 `튜토리얼 1 / 9` 형태로 총 9단계가 존재한다.

짧은 캐주얼 게임에서 시작 직후 9단계 튜토리얼은
사용자에게 다음과 같은 인상을 줄 수 있다.

```text
배워야 할 규칙이 많은 게임
튜토리얼이 오래 걸리는 게임
```

이번에 추가한 순위 보상 설명 때문에
튜토리얼 전체가 강의처럼 길어지지 않도록 한다.

### 목표

전체 튜토리얼을 가능하면 **5~6단계 수준으로 압축**한다.

---

# 2. 말풍선 내부 텍스트 가독성 문제

현재 일부 단계에서 본문 영역이 지나치게 좁아
다음처럼 거의 단어 단위로 줄바꿈되고 있다.

```text
밥그릇마다
순위별
사료
보상이
있어요!
```

또는

```text
꼭 1등이
아니어도
괜찮아요.
```

이 방식은 모바일 화면에서 매우 읽기 어렵다.

### 수정 원칙

- 본문 텍스트 영역에 최소한의 가로 폭을 확보한다.
- 한 문장이 2~3줄 이내에서 자연스럽게 읽히도록 한다.
- 설명과 예시 칩을 무리하게 한 줄에 같이 넣지 않는다.
- 버튼 때문에 본문 폭이 지나치게 줄어들지 않도록 한다.
- 필요하면 말풍선 자체의 가로 폭을 조금 넓힌다.
- 게임 화면을 가리지 않는 범위에서 tooltip 위치를 조정한다.

---

# 3. 설명을 말풍선 안에서 너무 많이 해결하고 있음

현재 다음 내용이 말풍선 내부에 직접 표시되고 있다.

```text
6 → 1등 → 40점
4 → 2등 → 20점
2 → 3등 → 10점
```

규칙 이해에는 도움이 되지만,
작은 튜토리얼 카드 안에 정보가 너무 많이 들어가
사용자가 실제 게임판보다 말풍선만 읽게 된다.

## 개선 방향

가능한 경우 **실제 게임 요소를 직접 강조해서 설명**한다.

예:

- 실제 1번 밥그릇의 보상칩 강조
- 40점 위에 `1등`
- 20점 위에 `2등`
- 10점 위에 `3등`

튜토리얼 중에만 임시 라벨을 추가해도 된다.

예:

```text
1등      2등      3등
40       20       10
```

말풍선에는 짧게:

```text
높은 숫자부터 순서대로 보상을 받아요.
꼭 1등이 아니어도 점수를 받을 수 있어요!
```

정도로 정리한다.

---

# 튜토리얼 전체 흐름 재구성

현재 9단계를 아래와 같이 5~6단계로 압축한다.

---

## STEP 1. 게임 목표

게임의 최종 목표를 짧게 설명한다.

예:

```text
사료를 가장 많이 모은 강아지가 승리해요!
```

기존 목표 설명 단계가 있다면 재사용한다.

---

## STEP 2. 순위별 보상 설명

1번 밥그릇을 spotlight 처리한다.

실제 보상 영역을 강조한다.

예:

```text
1등 40점
2등 20점
3등 10점
```

안내 문구:

```text
높은 숫자부터 순서대로 보상을 받아요.
꼭 1등이 아니어도 점수를 받을 수 있어요!
```

### 중요

현재의

```text
밥그릇마다 순위별 사료 보상이 있어요!
```

와

```text
꼭 1등이 아니어도 괜찮아요...
```

단계를 별도로 나누지 말고
**하나의 단계로 합친다.**

---

# STEP 3. 직접 선택 체험

사용자가 실제로 주사위를 선택하거나
현재 구현되어 있는 선택 체험을 진행한다.

이 단계에서는 설명을 길게 하지 않는다.

안내:

```text
직접 숫자를 골라볼까요?
```

또는 기존 문구를 재사용한다.

버튼:

```text
직접 해보기
```

---

# STEP 4. CLASH 체험

같은 숫자가 같은 밥그릇에서 만나면
CLASH가 발생하는 모습을 실제 게임판에서 보여준다.

예:

```text
6 + 6
→ CLASH
→ 두 주사위 제외
```

안내 문구:

```text
같은 숫자가 만나면 CLASH!
충돌한 주사위는 보상 경쟁에서 제외돼요.
```

### 중요

현재 CLASH 설명 단계와
CLASH 이후 순위 설명 단계를 지나치게 분리하지 않는다.

가능하면 하나의 흐름 안에서 연속 애니메이션으로 보여준다.

---

# STEP 5. CLASH 이후 순위 변화

CLASH 발생 직후
남은 주사위의 순위가 바뀌는 모습을 바로 보여준다.

예:

CLASH 전:

```text
6 / 6 / 4 / 2
```

CLASH:

```text
6 ↔ 6
```

CLASH 후:

```text
4 → 1등 → 40점
2 → 2등 → 20점
```

### 가능하면 말풍선 대신 실제 UI에서 표현

예:

- 6 주사위 두 개 fade out
- 4 주사위 highlight
- 1등 40점 보상 highlight
- 2 주사위 highlight
- 2등 20점 보상 highlight

안내 문구는 짧게:

```text
CLASH가 끝나면
남은 주사위끼리 다시 순위를 정해요!
```

---

# STEP 6. 최종 전략 + 결과 확인

마지막에는 규칙을 다시 길게 설명하지 않는다.

핵심 전략만 한 문장으로 정리한다.

권장:

```text
높은 숫자뿐 아니라
CLASH를 피하는 것도 중요해요!
```

또는:

```text
같은 숫자를 피하면서
더 좋은 순위의 보상을 노려보세요!
```

이후 튜토리얼 결과 / 라운드 결과 화면으로 자연스럽게 이동한다.

---

# 버튼 문구 단순화

현재 버튼 문구가 단계마다 다음처럼 계속 바뀌고 있다.

```text
순위 보상 보기
직접 해보기
CLASH 뒤 순위 보기
다음 체험
튜토리얼 마치기
```

사용자가 매번 다른 액션을 해석해야 하므로
튜토리얼 조작이 복잡해 보일 수 있다.

## 권장

기본 이동 버튼은 최대한 통일한다.

```text
다음
```

직접 조작이 필요한 단계에서만:

```text
직접 해보기
```

마지막 단계에서만:

```text
튜토리얼 완료
```

정도로 제한한다.

---

# 문구 수정

## 피해야 할 문구

```text
CLASH를 피해서 1등을 노려보세요!
```

이 표현은
사용자에게 1등만 점수를 받는 게임처럼 오해를 줄 수 있다.

---

## 권장 문구

### 순위 보상

```text
높은 숫자부터 순서대로 보상을 받아요.
꼭 1등이 아니어도 점수를 받을 수 있어요!
```

### CLASH

```text
같은 숫자가 만나면 CLASH!
충돌한 주사위는 보상 경쟁에서 제외돼요.
```

### CLASH 이후

```text
남은 주사위끼리 다시 순위를 정해요!
```

### 마지막 전략

```text
높은 숫자뿐 아니라
CLASH를 피하는 것도 중요해요!
```

---

# 문구 정확성 주의

다음 문구는 가능하면 사용하지 않는다.

```text
살아남으면 순위에 따라 사료를 받아요!
```

보상 슬롯보다 살아남은 주사위 수가 많을 수 있다면
모든 생존 주사위가 반드시 보상을 받는다고 오해할 수 있다.

보다 정확한 표현:

```text
살아남은 주사위 중
높은 숫자부터 순위 보상을 받아요!
```

또는:

```text
높은 숫자부터
준비된 순위 보상을 가져가요!
```

실제 게임 규칙에 맞는 표현을 선택한다.

---

# 실제 게임판 중심의 튜토리얼

이번 수정에서는
튜토리얼 카드 안에 모든 설명을 집어넣는 방식을 피한다.

우선순위:

1. 실제 밥그릇 강조
2. 실제 보상칩 강조
3. 실제 주사위 강조
4. 실제 CLASH 애니메이션 활용
5. 실제 순위 변화 시각화
6. 말풍선은 설명을 보조하는 역할만 수행

사용자가 게임 규칙을
'읽어서' 배우기보다
'게임판에서 직접 보고' 이해하도록 만든다.

---

# Spotlight / Tooltip UI 개선

현재 하이라이트 방식 자체는 유지해도 좋다.

다만 아래를 개선한다.

## Spotlight

- 강조 대상과 테두리 간격을 일정하게 유지한다.
- 너무 큰 영역을 한 번에 강조하지 않는다.
- 실제 설명 대상인 보상칩 / 밥그릇 / 주사위를 정확하게 가리킨다.

## Tooltip

- 본문 영역이 지나치게 좁아지지 않도록 한다.
- 한 단어씩 줄바꿈되지 않도록 한다.
- 예시와 설명이 충돌하면 세로 배치를 우선한다.
- 버튼은 tooltip 오른쪽 끝에 억지로 넣지 않아도 된다.
- 필요하면 버튼을 하단에 배치한다.

# 결과 화면 추가 QA

현재 튜토리얼 결과 화면에서 다음 상황이 확인되었다.

예:

```text
진도믹스 +50점
푸들 +50점
```

인데

```text
이번 라운드 사료왕
진도믹스 +50점
```

으로 단독 표시되고 있다.

## 확인 필요

실제 게임 코드에서 다음을 확인한다.

- 라운드 최고 점수가 동점일 경우 처리 규칙
- 단독 사료왕이 선정되는 별도 tie-break 규칙이 있는지
- 단순히 배열의 첫 번째 캐릭터를 승자로 표시하고 있지는 않은지
- 동점이면 공동 사료왕으로 표시해야 하는지

### 중요

실제 게임에 명확한 동점 처리 규칙이 있다면
그 규칙을 유지한다.

별도 규칙이 없는데 동일 점수 중 한 캐릭터만 단독 사료왕으로 표시된다면
표시 로직을 수정한다.

예:

```text
이번 라운드 공동 사료왕
진도믹스 · 푸들
+50점
```

등의 방식은 현재 게임 디자인과 규칙을 확인한 뒤 적용한다.

이번 작업에서 임의로 게임 규칙을 새로 만들지 않는다.

# 데이터 연동

튜토리얼 예시는 가능한 한 실제 게임 데이터를 사용한다.

예:

```ts
rewardSlots
currentBowlRewards
```

등 기존 데이터 구조를 먼저 확인한다.

튜토리얼에서

```text
40 / 20 / 10
```

을 직접 하드코딩하여
실제 밸런스 변경 후 잘못된 설명이 남지 않도록 한다.

# 게임 로직 변경 금지

이번 수정의 핵심은

```text
튜토리얼 압축
가독성 개선
시각적 설명 강화
문구 수정
```

이다.

다음 로직은 임의로 변경하지 않는다.

- CLASH 판정
- 점수 계산
- AI
- 주사위 선택
- 보상값
- 승패 조건
- 라운드 수
- 동점 규칙

단, 결과 화면에서 실제 규칙과 표시가 다른 버그가 발견되면
원인을 확인한 뒤 수정한다.

# 모바일 화면 QA

현재 기준 화면 크기뿐 아니라
실제 Toss Miniapp 환경을 고려한다.

확인 대상:

- iPhone 12 Pro 수준의 가로 화면
- 더 작은 화면
- Safe Area
- Toss 상단 영역
- 브라우저 UI 제외 실제 WebView
- Android
- iOS

확인 사항:

- tooltip 텍스트가 한 단어씩 줄바꿈되지 않는지
- 버튼이 본문을 침범하지 않는지
- tooltip이 게임판 밖으로 나가지 않는지
- 하단 영역과 겹치지 않는지
- spotlight 대상이 화면 밖으로 밀리지 않는지
- 게임 UI 자체의 위치가 튜토리얼 때문에 변하지 않는지

# 접근성

튜토리얼의 의미가
색상 / 화살표 / 위치만으로 전달되지 않도록 한다.

스크린리더에서는 예를 들어:

```text
1번 밥그릇.
1등 보상 40점,
2등 보상 20점,
3등 보상 10점.
```

CLASH 단계:

```text
같은 숫자 6 두 개가 충돌하여 제외됩니다.
남은 주사위 4가 1등,
주사위 2가 2등이 됩니다.
```

처럼 의미를 이해할 수 있어야 한다.

장식용 요소가 중복 낭독되지 않도록 주의한다.

---

# 최종 목표 UX

튜토리얼을 마친 사용자가 아래 네 가지를 이해하면 성공이다.

```text
1. 밥그릇에는 순위별 보상이 있다.
2. 높은 숫자가 더 좋은 순위가 된다.
3. 1등이 아니어도 보상을 받을 수 있다.
4. 같은 숫자는 CLASH로 제외되므로 높은 숫자만 고르는 것이 항상 정답은 아니다.
```

이 네 가지를
9개의 긴 설명 화면으로 배우는 것이 아니라
**5~6개의 짧은 체험 과정으로 이해하도록 수정한다.**

---

# QA 체크리스트

- [ ] 전체 튜토리얼이 가능하면 5~6단계로 압축되었다.
- [ ] 기존에 추가한 순위 보상 설명은 유지된다.
- [ ] 1등 이외의 순위도 보상을 받을 수 있다는 점이 전달된다.
- [ ] 순위 보상 설명이 하나의 단계로 자연스럽게 통합되었다.
- [ ] CLASH와 CLASH 이후 순위 재계산이 지나치게 분리되지 않았다.
