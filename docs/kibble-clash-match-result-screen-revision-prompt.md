# Codex CLI 수정 프롬프트 — 멍밥쟁탈전 최종 결과 화면 리디자인

## 0. 작업 범위

현재 구현된 `Match Result` 최종 결과 화면만 수정한다.

이번 작업에서 수정하지 않을 것:

- Home 화면
- Character Select 화면
- Game 화면
- Round Result 화면
- 주사위 규칙
- AI 로직
- 동률 상쇄 규칙
- 점수 계산 규칙
- 캐릭터 선택 로직
- 캐릭터 능력치

**최종 결과 화면이 승인되기 전에는 다른 화면을 수정하지 말고 멈춘다.**

---

# 1. 현재 화면 참고

현재 구현 화면을 다음 경로에 둔다.

```text
docs/reference/current-match-result.png
```

현재 화면의 주요 구성:

- 상단 중앙에 `오늘의 사료왕`
- 화면 중앙에 작은 원형 우승 캐릭터 이미지
- 우승 캐릭터 이름과 점수
- 하단에 작은 4인 순위 카드
- 최하단에 다시 하기·강아지 바꾸기·집으로 버튼
- 화면 전체에 큰 빈 공간

현재 구조와 데이터를 먼저 분석한 뒤 프레젠테이션 레이어를 수정한다.

---

# 2. 현재 화면의 문제

## 2.1 우승 연출보다 빈 공간이 더 크다

현재 화면 중앙과 상하단 사이에 의미 없는 빈 공간이 많다.

우승 캐릭터와 결과 정보가 화면 크기에 비해 너무 작아서 최종 결과 화면의 성취감이 약하다.

## 2.2 캐릭터가 작은 아바타처럼 보인다

우승 캐릭터가 원형 프레임 안에 작게 들어가 있어, 최종 우승 장면보다 프로필 카드처럼 보인다.

결과 화면에서는 우승 캐릭터를 큰 전신 또는 상반신 이미지로 보여줘야 한다.

## 2.3 정보 위계가 약하다

현재는 다음 정보의 시각적 차이가 충분하지 않다.

- 우승 캐릭터
- 우승 점수
- 사용자 본인의 결과
- 전체 순위
- 칭호
- 다시 하기 행동

사용자가 화면을 봤을 때 다음 순서로 읽혀야 한다.

```text
누가 우승했는가
→ 나는 몇 위인가
→ 각 플레이어의 최종 순위
→ 다음에 무엇을 할 수 있는가
```

## 2.4 사용자 결과가 묻혀 있다

사용자가 우승하지 않았을 때 자신의 순위와 점수가 우승 정보 아래의 작은 문장으로만 표시된다.

사용자 결과는 별도의 강조 카드로 보여줘야 한다.

## 2.5 데이터 불일치 가능성이 있다

현재 스크린샷에서는 다음 값이 서로 다르게 표시된다.

```text
중앙 문구:
내 강아지 최종 3위 · 150점

하단 순위:
진도믹스 4위 · 110점
```

사용자 캐릭터가 진도믹스라면 이는 데이터 불일치다.

UI를 수정하기 전에 다음을 확인한다.

- 실제 human player ID
- 실제 선택 캐릭터 ID
- 실제 최종 순위
- 실제 최종 점수
- 중앙 사용자 결과가 어떤 값을 참조하는지
- 하단 순위표가 어떤 값을 참조하는지

최종 결과 화면의 모든 값은 동일한 최종 결과 모델에서 가져와야 한다.

표시용으로 임의 숫자를 만들거나 별도 계산하지 않는다.

## 2.6 화면 문구가 승패 상황에 따라 달라지지 않는다

사용자가 패배했는데도 `오늘의 사료왕`이 사용자 축하 문구처럼 보일 수 있다.

제목과 설명을 사용자 승패에 따라 다르게 제공한다.

# 3. 목표 화면

## 핵심 문장

> 우승 캐릭터를 크게 보여주면서도, 사용자가 자신의 최종 순위와 다음 행동을 즉시 이해할 수 있는 캐릭터 중심 결과 화면

## 권장 레이아웃

```text
┌──────────────────────────────────────────────────────────────┐
│                     MATCH COMPLETE                           │
│                이번 판의 사료왕은 골든리트리버!             │
│                                                              │
│    [우승 캐릭터 큰 이미지]      [1위 골든리트리버]          │
│                                  190 사료 포인트             │
│                                  오늘의 칭호: 사료왕         │
│                                                              │
│    [내 결과 카드]                [전체 순위 1~4위]           │
│    진도믹스 · 4위 · 110점        캐릭터별 순위와 점수        │
│                                                              │
│       [같은 강아지로 한 판 더] [강아지 바꾸기] [집으로]    │
└──────────────────────────────────────────────────────────────┘
```

가로 화면에서는 좌우 2단 구성을 우선 사용한다.

- 왼쪽: 우승 캐릭터와 우승 연출
- 오른쪽: 우승 정보, 사용자 결과, 전체 순위
- 하단: 행동 버튼

화면 높이가 낮은 경우에는 캐릭터 이미지 크기와 장식을 먼저 줄이고, 점수와 버튼은 유지한다.

---

# 4. 제목과 결과 문구

## 4.1 사용자가 우승한 경우

제목:

```text
승리! 오늘의 사료왕
```

보조 문구:

```text
최고의 밥그릇 사냥꾼이 되었어요!
```

## 4.2 사용자가 우승하지 않은 경우

제목:

```text
이번 판의 사료왕
```

보조 문구:

```text
골든리트리버가 가장 많은 사료를 모았어요!
```

또는 실제 우승 캐릭터 이름을 사용한다.

## 4.3 공통 상단 라벨

```text
MATCH COMPLETE
4라운드 최종 결과
```

영문 라벨은 보조 정보로 작게 표시한다.

`오늘의 사료왕`을 무조건 고정하지 않는다.

---

# 5. 우승 캐릭터 영역

## 5.1 캐릭터 크기

- 현재 원형 아바타보다 최소 2~3배 크게 표시
- 가능하면 전신 또는 상반신 원본 이미지 사용
- 원형 프로필 프레임 안에 가두지 않음
- 캐릭터 귀, 꼬리, 발이 잘리지 않도록 `object-fit: contain`
- 화면 전체 높이의 약 35~50% 범위에서 조정

## 5.2 이미지 리소스

우승 포즈 전용 리소스가 있다면 우선 사용한다.

```text
assets/art/winner/
```

전용 이미지가 없다면 다음 순서로 fallback한다.

1. 실제 캐릭터 전신 이미지
2. 캐릭터 선택 화면용 이미지
3. 기존 아바타 이미지 확대

실제 이미지가 존재하면 CSS 강아지, 이모지, 단색 원으로 대체하지 않는다.

## 5.3 우승 연출

다음 요소를 적당히 사용한다.

- 왕관
- 작은 사료알 색종이
- 발바닥 모양 장식
- 부드러운 빛
- `1위` 배지

과도한 애니메이션과 화면 전체 흔들림은 사용하지 않는다.

동작 줄이기 설정에서는 정적인 장식만 표시한다.

---

# 6. 우승 정보

우승 캐릭터 옆에 다음 정보를 명확한 계층으로 표시한다.

```text
최종 1위
골든리트리버
190 사료 포인트
칭호 · 사료왕
```

요구사항:

- `190`을 가장 큰 숫자로 표시
- 단위 `사료 포인트`는 숫자보다 작게 표시
- 칭호는 작은 배지 형태
- 캐릭터 이름은 점수 다음으로 강하게 표시
- 장식 아이콘만으로 의미를 전달하지 않음

---

# 7. 사용자 결과 카드

사용자 캐릭터가 우승하지 않았더라도 사용자 결과를 독립된 카드로 강조한다.

예:

```text
내 결과
진도믹스
4위 · 110 사료 포인트
우승까지 80점 차이
```

요구사항:

- 사용자 캐릭터 아바타 표시
- `내 결과` 라벨 표시
- 실제 사용자 순위와 점수 표시
- 우승자와의 점수 차이는 계산 가능할 때만 표시
- 사용자가 우승했다면 별도 패배형 사용자 카드는 만들지 말고 우승 영역과 통합
- 색상만으로 사용자 카드를 구분하지 않고 `나` 또는 `내 결과` 텍스트 표시

---

# 8. 전체 순위표

하단에 가로로 작은 카드 4개를 나열하는 현재 구조를 개선한다.

## 권장 구조 A — 세로 순위 리스트

```text
1위  [아바타] 골든리트리버   190점
2위  [아바타] 푸들           180점
3위  [아바타] 퍼그           150점
4위  [아바타] 진도믹스       110점  나
```

가로형 화면의 오른쪽 영역에 4행으로 표시한다.

장점:

- 순위 비교가 쉽다.
- 점수 정렬이 명확하다.
- 작은 가로 카드보다 가독성이 높다.

## 권장 구조 B — 시상대

1~3위는 시상대로 보여주고 4위는 아래에 표시할 수 있다.

다만 정보가 복잡해지거나 화면이 좁아지면 구조 A를 사용한다.

## 순위표 요구사항

- 실제 최종 점수 내림차순
- 동점 처리 규칙을 기존 결과 모델 그대로 사용
- 사용자 행에 `나` 배지
- 1위 행에 왕관
- 캐릭터 이미지·이름·점수 모두 표시
- 별도의 별명이나 칭호는 한 줄 이하
- 너무 작은 글씨 금지

---

# 9. 버튼 구성

## 9.1 주요 버튼

문구:

```text
같은 강아지로 한 판 더
```

동작:

- 현재 선택 캐릭터 유지
- 새로운 매치 상태 생성
- 기존 Match Result 상태를 초기화
- 새 게임 시작

가장 강한 노란색 또는 주황색 버튼으로 표시한다.

## 9.2 보조 버튼

```text
강아지 바꾸기
```

동작:

```text
Match Result
→ Character Select
```

## 9.3 보조 버튼

```text
집으로
```

동작:

```text
Match Result
→ Home
```

## 9.4 배치

세 버튼을 너무 좁게 붙이지 않는다.

권장:

```text
[ 같은 강아지로 한 판 더 ]
[ 강아지 바꾸기 ] [ 집으로 ]
```

또는 충분한 가로 공간이 있으면 한 줄로 배치한다.

주요 버튼과 보조 버튼의 시각적 강도를 구분한다.

---

# 10. 화면의 빈 공간 줄이기

현재처럼 제목과 중앙 콘텐츠 사이, 중앙 콘텐츠와 하단 순위 사이에 큰 공백을 두지 않는다.

다음 기준을 적용한다.

- 메인 결과 콘텐츠가 화면 중앙 영역의 65~80%를 차지
- 우승 캐릭터 이미지가 충분히 크게 보임
- 결과 정보와 순위표를 서로 가까운 관련 그룹으로 배치
- 하단 버튼이 화면 프레임에 붙지 않도록 적절한 여백
- 장식을 늘려 공백을 채우지 말고 콘텐츠 크기와 배치를 조정

---

# 11. 배경과 스타일

기존 승인된 디자인 시스템을 유지한다.

- 크림·베이지 배경
- 따뜻한 브라운 텍스트
- 둥근 테두리
- 노란 주요 버튼
- 캐릭터별 대표 색상
- 발바닥·뼈다귀 장식

다만 결과 화면 전체가 단조로운 베이지 한 장처럼 보이지 않도록 다음을 사용할 수 있다.

- 우승 캐릭터 뒤의 연한 원형 빛
- 사용자 결과 카드의 연한 배경
- 순위 리스트의 약한 구분선
- 화면 모서리의 작은 색종이

여러 개의 중첩 카드와 과도한 그림자는 만들지 않는다.

---

# 12. 데이터 연결 요구사항

UI 수정 전에 최종 결과 데이터 흐름을 점검한다.

권장 단일 ViewModel:

```ts
type MatchResultViewModel = {
  winner: {
    playerId: string;
    characterId: CharacterId;
    displayName: string;
    score: number;
    title: string;
    imagePath: string;
  };
  humanResult: {
    playerId: string;
    characterId: CharacterId;
    displayName: string;
    rank: number;
    score: number;
    isWinner: boolean;
  };
  rankings: Array<{
    playerId: string;
    characterId: CharacterId;
    displayName: string;
    rank: number;
    score: number;
    isHuman: boolean;
  }>;
};
```

요구사항:

- `winner`, `humanResult`, `rankings`가 동일한 최종 결과 데이터에서 생성되어야 함
- 컴포넌트별로 순위나 점수를 다시 계산하지 않음
- 선택 캐릭터 이름을 하드코딩하지 않음
- 캐릭터 이미지도 실제 characterId로 연결
- 사용자 결과와 순위표가 항상 일치해야 함

---

# 13. 접근성

- 결과 제목을 실제 텍스트로 제공
- 우승 캐릭터 이미지에 접근 가능한 설명 제공
- 순위표는 논리적인 읽기 순서로 구성
- `1위, 골든리트리버, 190점`처럼 한 행의 정보가 함께 읽히게 함
- 사용자 행에 `내 캐릭터` 상태를 프로그램적으로 제공
- 버튼의 접근 가능한 이름과 화면 문구 일치
- 포커스 순서:
  1. 결과 제목
  2. 우승 정보
  3. 내 결과
  4. 전체 순위
  5. 같은 강아지로 한 판 더
  6. 강아지 바꾸기
  7. 집으로
- 색상만으로 순위나 사용자 여부를 표현하지 않음
- 충분한 명도 대비
- 동작 줄이기 설정 지원

---

# 14. 가로형 반응형

최소 확인 해상도:

```text
1920×1080
1280×720
932×430
844×390
```

요구사항:

- 화면 전체 세로 스크롤을 되도록 사용하지 않음
- 낮은 화면에서는 캐릭터 이미지와 장식을 먼저 축소
- 제목, 사용자 결과, 주요 버튼은 잘리지 않음
- Safe Area 반영
- 순위 리스트 텍스트가 지나치게 작아지지 않음
- 주요 버튼의 터치 영역 유지

---

# 15. 금지사항

- 다른 화면 수정
- 점수 계산 규칙 변경
- 임의의 점수나 순위 표시
- 사용자 결과와 순위표를 서로 다른 데이터로 계산
- 우승 캐릭터를 작은 원형 아바타로만 표시
- 거대한 빈 공간 유지
- 모든 정보를 하단의 작은 카드에 몰아넣기
- 캐릭터 이미지 대신 이모지 사용
- 실제 캐릭터 이미지가 있는데 CSS 도형으로 대체
- 새로운 공유·광고·보상 기능 추가
- 사용자 승패와 관계없이 제목을 무조건 `오늘의 사료왕`으로 고정
- 이미지에 점수나 이름을 합성
- 기존 테스트 삭제 또는 약화

# 16. 테스트 요구사항

최소 다음을 검증한다.

1. winner가 실제 1위 플레이어와 일치하는가
2. humanResult의 순위와 rankings의 사용자 행 순위가 일치하는가
3. humanResult의 점수와 rankings의 사용자 행 점수가 일치하는가
4. 사용자 우승 시 승리형 제목이 표시되는가
5. 사용자 패배 시 중립형 제목이 표시되는가
6. 1위 캐릭터의 실제 이미지가 표시되는가
7. 같은 강아지로 한 판 더가 현재 캐릭터를 유지하는가
8. 강아지 바꾸기가 Character Select로 이동하는가
9. 집으로가 Home으로 이동하는가
10. 주요 가로 해상도에서 콘텐츠가 잘리지 않는가
11. 기존 게임 로직 테스트가 모두 통과하는가

# 17. 완료 기준

## 데이터

- 중앙 사용자 결과와 전체 순위표의 순위·점수가 일치한다.
- 우승 캐릭터와 1위 순위 행이 일치한다.
- 모든 결과가 단일 ViewModel에서 나온다.

## 시각

- 우승 캐릭터가 화면의 주인공으로 크게 보인다.
- 화면의 큰 빈 공간이 제거된다.
- 사용자의 최종 결과가 별도로 강조된다.
- 전체 순위를 쉽게 비교할 수 있다.
- 주요 행동 버튼이 분명하다.
- 기존 캐릭터 선택·게임 화면과 같은 디자인 시스템으로 느껴진다.

## 기능

- 같은 캐릭터 재시작
- 캐릭터 변경
- 홈 이동

이 모두 정상 동작한다.

## 기술

- 테스트 통과
- 빌드 성공
- 주요 가로 해상도 확인
- 접근성 요구사항 반영
