# Codex CLI 프롬프트 — 캐릭터 선택 및 이미지 리소스 기반 UI 전면 보강

## 역할

너는 Cocos Creator 3.8.7과 TypeScript 기반의 2D 모바일 캐주얼 게임을 개발하는 시니어 게임 UI 개발자다.

프로젝트:

- 한글명: `멍밥쟁탈전`
- 영문명: `Kibble Clash`

이번 작업의 목적은 현재 동작 중인 게임 규칙을 유지하면서 다음을 구현하는 것이다.

1. 게임 시작 전 플레이 캐릭터 선택
2. 제공된 이미지 리소스 반영
3. 게임 진행 화면에 강아지 캐릭터 복원
4. 밥그릇 주변 경쟁 상황을 캐릭터 토큰으로 시각화
5. 라운드 결과와 최종 결과를 캐릭터 중심으로 개선
6. 기존 대시보드형 UI를 실제 강아지 보드게임처럼 보이게 개선

---

# 1. 먼저 확인할 파일

프로젝트 루트에 다음 문서와 리소스가 있다고 가정한다.

```text
docs/reference/kibble-clash-image-resource-list.md
```

해당 문서를 먼저 읽고 다음을 확인한다.

- 리소스 파일명
- 각 이미지의 역할
- 캐릭터 고정 설정
- fallback 요구사항

이미지 리소스는 다음 경로에 배치되어 있다.

```text
assets/art/
```

파일이 일부 누락되어도 작업을 중단하지 않는다.

누락 파일은 임시 플레이스홀더로 처리하고, 누락 목록을 최종 보고에 작성한다.

# 2. 현재 프로젝트 분석

코드를 수정하기 전에 다음을 확인한다.

- 현재 화면 흐름
- Home 화면
- Game 화면
- Round Result 화면
- Match Result 화면
- 현재 플레이어 데이터 모델
- 캐릭터가 플레이어 ID에 고정되어 있는지 여부
- 사용자와 AI를 구분하는 방식
- 이미지 및 SpriteFrame 로딩 방식
- 로컬 저장 방식
- 현재 자동 테스트
- 현재 빌드 명령

분석 후 짧은 구현 계획을 먼저 작성한다.

기존 게임 규칙과 도메인 로직을 UI 편의를 위해 다시 작성하지 않는다.

# 3. 절대 변경하지 않을 게임 규칙

- 총 4라운드
- 사용자 1명과 AI 3명
- 플레이어별 주사위 8개
- 남은 주사위를 모두 굴림
- 나온 숫자 중 하나 선택
- 선택한 눈의 주사위를 같은 번호 밥그릇에 전부 배치
- 라운드 시작 전 각 밥그릇의 사료 보상 카드 공개
- 각 밥그릇은 보상 합계가 최소 기준 이상이 될 때까지 카드 배치
- 같은 주사위 개수의 플레이어는 동률 상쇄
- 상쇄 후 살아남은 플레이어가 주사위 수 순서대로 큰 보상 카드부터 한 장씩 획득
- 기존 AI 의사결정
- 기존 점수 계산
- 기존 시드 및 RNG
- 기존 테스트

이번 작업은 다음만 다룬다.

- 화면 흐름
- 캐릭터 선택
- 플레이어와 캐릭터 매핑
- 이미지 리소스 반영
- UI와 연출

# 4. 새로운 화면 흐름

기존:

```text
Home
→ Game
```

수정:

```text
Home
→ Character Select
→ Game
→ Round Result
→ Game
→ Match Result
```

## Home

`게임 시작`을 누르면 Game으로 바로 이동하지 않고 Character Select로 이동한다.

홈 화면에서 마지막으로 선택했던 캐릭터를 작은 아바타로 표시해도 좋다.

## Character Select

신규 화면을 만든다.

제목:

```text
플레이할 강아지를 골라주세요
```

선택 가능한 캐릭터:

- 진도믹스
- 푸들
- 퍼그
- 골든리트리버

각 카드에 다음을 표시한다.

- 캐릭터 선택용 이미지
- 캐릭터 이름
- 짧은 성격 문구
- 대표 색상
- 대표 문양
- 선택 상태

성격 문구:

- 진도믹스: `씩씩하고 눈치 빠른 밥그릇 사냥꾼`
- 푸들: `귀여운 얼굴 뒤에 숨은 전략가`
- 퍼그: `한 그릇에 과감하게 몰아붙이는 승부사`
- 골든리트리버: `안전한 보상을 차근차근 챙기는 평화주의자`

버튼:

- `이 강아지로 시작`
- `뒤로`

캐릭터 카드를 선택하지 않은 상태에서는 시작 버튼을 비활성화하거나 기본 캐릭터를 명확히 선택한 상태로 제공한다.

# 5. 사용자 캐릭터와 AI 배정

사용자가 선택한 캐릭터가 사용자 플레이어가 된다.

나머지 세 캐릭터는 AI 플레이어에게 배정한다.

예시:

```text
선택: 퍼그

사용자:
- 퍼그

AI:
- 진도믹스
- 푸들
- 골든리트리버
```

## 구현 요구사항

플레이어의 역할과 캐릭터를 분리한다.

잘못된 구조:

```ts
player1 === jindoMix
player2 === poodle
```

권장 구조:

```ts
type CharacterId =
  | 'jindo-mix'
  | 'poodle'
  | 'pug'
  | 'golden-retriever';

type Player = {
  id: string;
  controllerType: 'human' | 'ai';
  characterId: CharacterId;
};
```

즉, 사용자가 어떤 캐릭터를 골라도 게임 규칙이 정상 동작해야 한다.

캐릭터별 능력 차이는 없다.

---

# 6. 선택 캐릭터 저장

마지막 선택 캐릭터를 로컬 저장한다.

요구사항:

- 저장 키는 상수로 관리
- 값이 없거나 유효하지 않으면 진도믹스를 기본값으로 사용
- 저장소 접근은 별도 어댑터로 분리
- 브라우저와 앱인토스 환경에서 안전하게 fallback
- 매 게임 시작 전에 캐릭터를 변경할 수 있음

저장된 캐릭터가 자동으로 선택되어도 Character Select 화면은 건너뛰지 않는다.

---

# 7. 이미지 리소스 로딩

## 경로

리소스는 아래 구조를 따른다.

```text
assets/art/characters/
assets/art/avatars/
assets/art/bowls/
assets/art/rewards/
assets/art/effects/
assets/art/backgrounds/
assets/art/winner/
```

## 구현 원칙

- 이미지 경로를 화면 컴포넌트에 하드코딩하지 않는다.
- `CharacterVisualConfig` 또는 유사한 설정 객체를 만든다.
- 캐릭터 ID로 선택 이미지, 아바타, 우승 이미지를 찾을 수 있게 한다.
- 이미지 로드 실패 시 품종명 첫 글자나 단순 SVG/도형으로 fallback한다.
- 누락된 이미지 하나 때문에 게임 전체가 중단되지 않게 한다.

예시:

```ts
type CharacterVisualConfig = {
  id: CharacterId;
  displayName: string;
  selectImage: string;
  avatarImage: string;
  winnerImage: string;
  primaryColor: string;
  symbol: string;
  personalityText: string;
};
```

# 8. 게임 진행 화면 개선

현재 게임 진행 화면의 기능은 유지하되 캐릭터를 다시 화면 중심으로 가져온다.

## 8.1 플레이어 HUD

각 플레이어 HUD에 다음을 표시한다.

- 실제 캐릭터 아바타
- 이름
- 현재 점수
- 남은 주사위
- 사용자 또는 AI 여부
- 현재 턴 강조

텍스트 이름표만 보여주는 상태를 허용하지 않는다.

## 8.2 밥그릇 주변 토큰

밥그릇에 배치된 주사위 수를 캐릭터 아바타 토큰과 개수로 표시한다.

예:

```text
[진도믹스 얼굴] ×3
[퍼그 얼굴] ×2
```

요구사항:

- 배치 수가 0인 캐릭터는 기본 게임판에서 숨길 수 있음
- 색상만 사용하지 않음
- 얼굴, 문양, 숫자 모두 제공
- 동률 캐릭터는 충돌 아이콘 또는 연결 표시
- 현재 우세 캐릭터는 작은 왕관 또는 리더 표시
- 우세 표시는 `현재 기준 예상`임을 나타낼 것

## 8.3 밥그릇 비주얼

기존 빈 박스나 단순 타원 대신 제공된 밥그릇 이미지를 사용한다.

각 밥그릇 위나 주변에 다음을 표시한다.

- 번호
- 총 보상
- 개별 보상 카드
- 캐릭터 토큰
- 현재 우세 또는 동률 상태

번호와 점수는 이미지에 포함하지 않고 UI 텍스트로 올린다.

## 8.4 보상 카드

건식사료, 습식사료, 간식 이미지를 사용한다.

MVP에서는 보상 종류에 따른 능력 차이는 없다.

각 카드에 숫자 포인트를 UI 텍스트로 표시한다.

## 8.5 숫자 선택과 밥그릇 연결

사용자가 선택 가능한 숫자 버튼을 포커스하거나 선택하면:

- 대응 밥그릇 하이라이트
- 배치 예정 캐릭터 토큰 표시
- 배치 주사위 수 표시
- 나머지 밥그릇은 약하게 처리
- 설명 문구 제공

예:

```text
4번 밥그릇에 퍼그 주사위 2개를 전부 놓습니다.
```

# 9. Kibble Clash 상쇄 연출

동률 상쇄는 대표 게임 이벤트다.

제공된 파일:

```text
assets/art/effects/kibble-clash-burst.png
```

연출 순서:

1. 동률 캐릭터 토큰 강조
2. 두 토큰 흔들림
3. 충돌 버스트 표시
4. UI 텍스트로 `KIBBLE CLASH!`와 `동률 상쇄` 표시
5. 상쇄 토큰 흐려짐 또는 튕겨 나감
6. 살아남은 순위 표시
7. 보상 카드가 획득 캐릭터 쪽으로 이동 또는 강조

주의:

- 게임 상태 변경은 연출 시작 전에 한 번만 확정
- 애니메이션 콜백이 점수를 다시 변경하지 않음
- 연출 중 중복 입력 차단
- 건너뛰기 지원
- 동작 줄이기 설정에서는 단순 페이드와 텍스트로 대체
- 상쇄 결과를 반드시 텍스트로도 안내

# 10. 라운드 결과 화면

현재의 정산 정보는 유지한다.

다음 요소를 추가한다.

- 해당 라운드에서 가장 많은 보상을 얻은 캐릭터 아바타
- 동률 상쇄가 발생한 밥그릇 강조
- 밥그릇별 보상 획득 캐릭터를 얼굴 토큰으로 표시
- 사용자 캐릭터의 라운드 획득 점수 강조
- `다음 라운드` 버튼

표만 있는 화면으로 만들지 않는다.

---

# 11. 최종 결과 화면

1위 캐릭터를 화면의 주인공으로 표시한다.

제공된 우승 이미지가 있으면 사용한다.

```text
assets/art/winner/{characterId}_win.png
```

필수 표시:

- 1위 캐릭터 이미지
- 최종 순위
- 총 사료 포인트
- 오늘의 칭호
- `한 판 더`
- `집으로`

사용자가 우승하지 못해도 사용자 캐릭터의 순위와 점수를 명확히 보여준다.

`한 판 더`를 누르면 Character Select로 이동할지, 동일 캐릭터로 즉시 시작할지 명확히 선택한다.

권장:

- `같은 강아지로 한 판 더`
- `강아지 바꾸기`
- `집으로`

# 13. 접근성 요구사항

- 캐릭터를 색상만으로 구분하지 않음
- 캐릭터 이미지, 이름, 문양, 색상 함께 제공
- Character Card를 실제 선택 가능한 버튼 또는 라디오 컨트롤로 구현
- 선택 상태를 테두리, 체크 아이콘, 문구로 표시
- 이미지에 대체 텍스트 또는 접근 가능한 이름 연결
- 숫자 선택 버튼 예:
  - `숫자 4, 주사위 2개를 4번 밥그릇에 전부 놓기`
- 현재 턴 변경을 텍스트로 알림
- 상쇄 결과를 텍스트로 알림
- 터치 대상 크기 확보
- 충분한 명도 대비
- 동작 줄이기 및 연출 건너뛰기 고려

# 16. 최소 자동 테스트

1. 사용자가 네 캐릭터 중 하나를 선택할 수 있는가
2. 선택한 캐릭터가 human 플레이어에게 배정되는가
3. 나머지 세 캐릭터가 AI에게 중복 없이 배정되는가
4. 어떤 캐릭터를 선택해도 게임 규칙이 동일하게 동작하는가
5. 저장된 캐릭터가 다음 Character Select에서 기본 선택되는가
6. 유효하지 않은 저장 값은 기본 캐릭터로 fallback하는가
7. 게임 HUD에 선택한 캐릭터가 표시되는가
8. 밥그릇 토큰에 실제 플레이어 캐릭터가 반영되는가
9. 최종 결과 화면에 실제 1위 캐릭터가 표시되는가
10. 일부 이미지가 없어도 게임이 실행되는가
11. 기존 주사위·상쇄·정산 테스트가 모두 통과하는가

---

# 17. 완료 기준

- Home의 게임 시작이 Character Select로 연결된다.
- 네 마리 중 플레이할 강아지를 선택할 수 있다.
- 선택 캐릭터가 human 플레이어가 된다.
- 나머지 세 캐릭터는 AI가 된다.
- 선택한 캐릭터가 HUD, 턴 안내, 토큰, 결과 화면에 일관되게 반영된다.
- 게임 진행 화면에서 실제 강아지 캐릭터가 보인다.
- 밥그릇 주변 경쟁 상황이 얼굴 토큰과 개수로 표시된다.
- 이미지가 누락되어도 fallback이 작동한다.
- 기존 게임 규칙은 바뀌지 않는다.
- 테스트가 통과한다.
- 빌드가 성공한다.
- 작업 결과와 누락 리소스가 문서화된다.

---

# 18. 하지 말아야 할 것

- 사용자를 무조건 진도믹스에 고정
- 캐릭터 선택을 외형만 바꾸는 가짜 선택으로 구현
- 캐릭터마다 능력치를 임의로 추가
- 기존 정산 규칙 수정
- 이미지에 점수나 이름을 직접 박아 넣기
- 누락 이미지 때문에 앱 전체 실행 중단
- 캐릭터를 색상만으로 구분
- 기존 테스트 삭제
- UI를 다시 대시보드형 표 중심으로 구성
- 외부 이미지를 임의로 다운로드
