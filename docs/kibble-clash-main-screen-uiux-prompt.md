# Codex CLI 프롬프트 — 멍밥쟁탈전 메인 화면 UI/UX 구현

## 역할

너는 Cocos Creator 3.8.7 + TypeScript 기반의 모바일 캐주얼 게임 UI를 구현하는 시니어 개발자다.

프로젝트:

- 한글명: `멍밥쟁탈전`
- 영문명: `Kibble Clash`
- 플랫폼: Apps in Toss
- 화면 방향: 가로형
- 우선 비율: 16:9

이번 작업에서는 **캐릭터 선택 전에 표시되는 메인 화면만 구현한다.**

Character Select, Game, Round Result, Match Result 화면은 이번 작업에서 디자인을 수정하지 않는다.

---

# 1. 목표

현재 메인 화면을 다음 방향으로 다시 구성한다.

> 밝고 따뜻한 강아지 캐주얼 게임의 첫인상을 주고, 사용자가 게임 제목과 `게임 시작` 버튼을 즉시 인식할 수 있는 화면

메인 화면의 역할:

1. 게임의 분위기 전달
2. 게임 제목 표시
3. 게임 시작
4. 게임 방법 확인
5. 설정 진입
6. 캐릭터 선택 화면으로 이동

메인 화면에 점수표, 시드 번호, 디버그 정보, 세부 게임 상태를 표시하지 않는다.

---

# 2. 작업 전 확인

코드를 수정하기 전에 다음을 확인하고 짧게 보고한다.

1. 현재 Home/Main 화면 컴포넌트
2. 화면 전환 방식
3. Character Select 화면의 경로 또는 Scene ID
4. `assets/art/characters/`의 실제 파일 목록
5. 캐릭터 이미지의 크기와 배경 포함 여부
6. 로고 또는 메인 배경 리소스 존재 여부
7. 공통 버튼, 디자인 토큰, Safe Area 처리 방식
8. 기존 테스트와 빌드 명령

보고 형식:

```text
## 현재 구조
- Home/Main 컴포넌트
- 화면 전환 방식
- Character Select 연결 상태

## 사용 가능한 리소스
- 캐릭터 파일
- 로고 파일
- 배경 파일
- 누락 파일

## 구현 계획
- 유지할 코드
- 수정할 파일
- 새로 만들 컴포넌트
- 테스트 항목
```

명확한 차단 요소가 없다면 분석 후 구현을 계속한다.

---

# 3. 캐릭터 구성

현재 프로젝트에 존재하는 실제 이미지 파일을 기준으로 다음 캐릭터를 사용할 수 있다.

- 진도믹스
- 푸들
- 퍼그
- 골든리트리버
- 웰시코기

실제 파일이 없는 캐릭터는 화면에 넣지 않는다.

메인 화면은 캐릭터 선택 전 화면이므로 특정 캐릭터 한 마리를 사용자 캐릭터로 강조하지 않는다. 여러 강아지가 함께 출전하는 **단체 히어로 장면**으로 표현한다.

`assets/art/characters/`에 실제 이미지가 있으면 반드시 그 파일을 사용한다.

다음으로 대체하지 않는다.

- 이모지
- CSS로 그린 강아지
- 단색 원
- 품종 첫 글자
- 외부에서 다운로드한 이미지

---

# 4. 화면 구조

가로형 모바일 화면에서 다음 구조를 우선 적용한다.

```text
┌───────────────────────────────────────────────────────┐
│                                                       │
│              강아지 캐릭터 그룹 / 히어로 장면        │
│                                                       │
│                    멍밥쟁탈전                         │
│                    KIBBLE CLASH                       │
│          주사위를 굴려 최고의 밥그릇을 차지하세요    │
│                                                       │
│                   [ 게임 시작 ]                       │
│               [ 게임 방법 ] [ 설정 ]                 │
│                                                       │
│              최근 선택 캐릭터 또는 작은 안내         │
│                                                       │
└───────────────────────────────────────────────────────┘
```

시각적 우선순위:

1. 게임 제목
2. 강아지 캐릭터 그룹
3. `게임 시작`
4. 한 줄 설명
5. `게임 방법`, `설정`
6. 최근 선택 정보

---

# 5. 디자인 방향

## 전체 톤

- 밝은 크림·베이지 배경
- 따뜻한 브라운 라인
- 둥근 모서리
- 부드러운 깊이감과 그림자
- 노란색 또는 주황색의 주요 버튼
- 발바닥, 뼈다귀, 사료알 장식
- 가족 친화적인 모바일 캐주얼 게임 분위기

다음처럼 보이면 안 된다.

- 업무용 대시보드
- 운영자 화면
- 일반 웹사이트 랜딩 페이지
- 빈 공간이 많은 프레젠테이션 화면

## 배경

전용 메인 배경 리소스가 있으면 사용한다.

전용 배경이 없다면 다음으로 구성한다.

- 크림색 기본 배경
- 은은한 발바닥 패턴
- 화면 가장자리의 작은 뼈다귀·사료알 장식
- 중앙 콘텐츠를 방해하지 않는 단순한 색면

진한 검정 또는 갈색 그라데이션을 캐릭터 뒤에 깔지 않는다.

---

# 6. 캐릭터 그룹 배치

캐릭터를 화면 네 귀퉁이에 작은 스티커처럼 흩어놓지 않는다.

다음 두 방식 중 현재 리소스에 적합한 방식을 선택한다.

## 권장안 A — 제목 위 반원형 그룹

- 4~5마리를 제목 위에 반원형으로 배치
- 중앙 캐릭터를 약간 크게
- 양옆 캐릭터를 조금 작게
- 캐릭터 간 크기 차이는 과도하지 않게
- 단체 출전 사진처럼 보이게 함

## 권장안 B — 좌우 히어로 그룹

- 제목과 버튼을 중앙에 배치
- 캐릭터 2~3마리를 좌측, 나머지를 우측에 자연스럽게 배치
- 중앙 버튼 영역을 침범하지 않음
- 캐릭터가 서로 다른 방향을 바라보거나 따로 노는 느낌을 피함

## 이미지 배경 처리

캐릭터 이미지에 배경색이 포함되어 있다면 사각형 이미지 경계가 보이지 않게 처리한다.

가능한 방법:

- 알파 마스크
- 부드러운 그라데이션 마스크
- 메인 배경과 동일한 색으로 자연스럽게 블렌딩
- 카드형 프레임 안에 통일된 방식으로 배치

원본 이미지가 투명 PNG라면 그대로 사용한다.

캐릭터의 귀, 발, 꼬리가 잘리지 않게 한다.

# 7. 제목과 설명

## 제목

```text
멍밥쟁탈전
KIBBLE CLASH
```

전용 로고 이미지가 있으면 사용한다.

로고 이미지가 없다면 실제 UI 텍스트로 구현한다.

요구사항:

- 한글 제목을 가장 크게
- 영문 제목은 보조 크기
- 텍스트가 캐릭터에 가리지 않음
- 제목을 배경 이미지에 합성하지 않음
- 모바일 화면에서 선명하게 읽힘

## 한 줄 설명

다음 중 하나를 사용한다.

```text
주사위를 굴려 최고의 밥그릇을 차지하세요!
```

또는

```text
같은 수는 상쇄! 살아남아 사료를 차지하세요.
```

한 문장만 표시한다.

---

# 8. 버튼

## 게임 시작

문구:

```text
게임 시작
```

동작:

```text
Home → Character Select
```

요구사항:

- 화면에서 가장 크고 강한 버튼
- 노란색 또는 주황색
- 충분한 터치 영역
- 눌림, 포커스, 비활성 상태 제공
- Game 화면으로 직접 이동하지 않음
- 마지막 선택 캐릭터가 있더라도 Character Select를 생략하지 않음

## 게임 방법

문구:

```text
게임 방법
```

기존 게임 방법 화면이 있으면 연결한다.

없다면 Home 내부 모달로 다음 네 단계만 보여준다.

1. 남은 주사위를 모두 굴립니다.
2. 숫자 하나를 골라 같은 숫자의 주사위를 전부 놓습니다.
3. 같은 개수로 맞선 강아지는 모두 상쇄됩니다.
4. 살아남은 순서대로 큰 사료 보상을 받습니다.

모달은 닫기 버튼과 포커스 복귀를 지원한다.

## 설정

문구:

```text
설정
```

현재 실제로 지원되는 기능만 제공한다.

예:

- 배경음 켜기/끄기
- 효과음 켜기/끄기
- 동작 줄이기

기능이 없다면 비어 있는 설정 화면을 만들지 않는다.

## 사용자 화면에서 제거

다음은 노출하지 않는다.

- 시드 번호
- 새 게임판 디버그 버튼
- FPS
- 내부 상태
- 개발 URL
- 테스트 메뉴

필요하면 개발 모드에서만 표시한다.

---

# 9. 최근 선택 캐릭터

마지막 선택 캐릭터 저장 기능이 이미 있다면 하단에 보조 정보로 표시할 수 있다.

예:

```text
최근 선택: 퍼그
```

- 작은 원형 아바타와 이름
- 제목과 게임 시작 버튼보다 약하게
- 클릭해도 게임으로 바로 이동하지 않음
- `게임 시작`을 누르면 Character Select로 이동

저장 기능이 아직 없다면 이번 작업에서 새로 만들 필요는 없다.

# 10. 애니메이션

허용되는 가벼운 연출:

- 로고가 짧게 등장
- 캐릭터가 아주 약하게 숨 쉬듯 움직임
- 사료알 또는 발바닥 장식이 한 번 반짝임
- 게임 시작 버튼이 처음 한 번 부드럽게 강조됨

금지:

- 캐릭터 전체가 계속 점프
- 화면 전체 흔들림
- 입력을 막는 긴 인트로
- 반복 애니메이션으로 인한 산만함

동작 줄이기 설정에서는 정적인 화면으로 제공한다.

# 12. 접근성

- `게임 시작`, `게임 방법`, `설정`은 실제 버튼으로 구현
- 화면 문구와 접근 가능한 이름 일치
- 포커스 표시 제거 금지
- 키보드 및 보조 입력으로 조작 가능
- 버튼 상태를 색상만으로 구분하지 않음
- 충분한 명도 대비
- 한글·영문 제목을 실제 텍스트로 제공
- 장식 이미지는 보조기술에서 제외
- 게임 방법 모달이 열리면 포커스를 내부로 이동
- 닫으면 원래 버튼으로 포커스 복귀
- 동작 줄이기 지원

# 13. 권장 컴포넌트

실제 프로젝트 구조에 맞게 조정할 수 있다.

```text
HomeScreen
├─ HomeBackground
├─ CharacterGroup
│  └─ HomeCharacter × 4~5
├─ GameLogo
├─ GameTagline
├─ HomeActionButtons
│  ├─ StartGameButton
│  ├─ HowToPlayButton
│  └─ SettingsButton
├─ RecentCharacterBadge
├─ HowToPlayModal
└─ SettingsModal
```

캐릭터 이미지 경로를 여러 컴포넌트에 반복 하드코딩하지 않는다.

기존 `CharacterVisualConfig` 또는 유사한 설정 객체가 있다면 재사용한다.

# 15. 테스트

최소 다음을 검증한다.

1. Home 화면이 정상 렌더링되는가
2. `게임 시작`이 Character Select로 이동하는가
3. Game으로 직접 이동하지 않는가
4. `게임 방법` 모달이 열리고 닫히는가
5. 설정 버튼이 지원되는 설정 UI를 여는가
6. 일부 캐릭터 이미지가 없어도 화면 전체가 중단되지 않는가
7. 버튼에 접근 가능한 이름이 존재하는가
8. 주요 가로 해상도에서 제목과 버튼이 잘리지 않는가
9. 기존 게임 로직 테스트가 모두 통과하는가

# 16. 완료 기준

## 시각

- 밝고 따뜻한 강아지 캐주얼 게임처럼 보인다.
- 게임 제목이 가장 먼저 보인다.
- 캐릭터들이 하나의 단체 장면처럼 보인다.
- 캐릭터가 화면 구석에 따로 흩어져 있지 않다.
- 의미 없는 큰 빈 공간이 없다.
- `게임 시작`이 가장 강한 행동이다.
- 대시보드나 일반 웹사이트처럼 보이지 않는다.

## 기능

- 게임 시작이 Character Select로 이동한다.
- 게임 방법이 동작한다.
- 설정은 실제 지원 범위 안에서 동작한다.
- 기존 게임 규칙은 변경되지 않는다.

## 기술

- 실제 캐릭터 이미지가 사용된다.
- 이미지 누락 fallback이 있다.
- 주요 가로 해상도에서 잘리지 않는다.
- 테스트가 통과한다.
- 빌드가 성공한다.
